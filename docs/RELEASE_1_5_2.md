# 1.5.2 热修候选与验收

状态：**NO-GO / 尚未构建、尚未发布**。用户已授权准备并发布 1.5.2；授权不替代验收结果。已有 v1.5.1 标签和预发布安装包保持不可变。

## 修复范围

- 可选快速视觉推荐的抽帧进程失败、超时、文件读取错误不再中断整个导入；保留告警并降级到字幕方案，抽帧失败不调用视觉服务。
- 内容任务返回有阶段但没有错误码的结构化失败时，保留 PipelineFailure 的阶段；Sentry 只上传阶段枚举，不上传错误正文、素材路径或模型内容。
- 大纲请求全部遭遇 429、500、超时或断网时保留对应失败码和恢复提示；模型回答无法形成大纲时标记 invalid_response。失败仍终止本次制作，不伪造成功，也不增加自动请求。
- Studio 状态读写在同一事务锁内；Windows 原子替换被临时占用时有界重试同一份快照，持续拒绝时保留旧文件并报错，不重复执行制作或状态变更。
- 包含 1.5.1 的既有热修，范围见 [上一候选记录](RELEASE_1_5_1.md)。封面主体选择的后续改进继续单独迭代。

## 复现与验证

最终 1.5.1 安装包在隔离目录离线复现了抽帧异常逃逸，以及无错误码的管线失败被包装为 RuntimeError。新增边界回归在修复前 5 项失败；大纲分类补充回归在修改前另有 5 项失败。补充修复后相关 67 项回归通过，均不调用外部服务。

缺口来自只验证正常推荐、已分类的模型错误和有错误码的管线失败，没有覆盖进程异常及无错误码的失败边界。新增用例覆盖这些实际调用边界，并检查隐私脱敏；仍需新包双平台验证成功、失败与修正后恢复。

追加状态文件回归修复前 5 项失败、1 项通过；修复后与相关 Studio 场景共 102 项通过。真实 Windows 文件共享冲突回归已加入 Windows CI，结果待验证。状态文件 PermissionError 告警没有系统及具体权限错误号，已验证的占用边界不能直接证明旧事件的根因。

两条远端制作 RuntimeError 的具体触发原因因旧事件没有正文、阶段及客户端构建信息而尚未确认。边界复现不能当作远端根因证明；该未知主流程故障保留 blocker，需新构建的可定位事件或对应条件的实际证据闭环。
