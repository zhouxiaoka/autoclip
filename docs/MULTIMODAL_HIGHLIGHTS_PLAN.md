# 多模态高光检索：Seed 接入与 Jev 实验

日期：2026-09-21。状态：官方资料研究与接入设计，尚未调用模型、运行真实素材评测或实现产品代码。本文取代旧规划中“第 5 周才开始视觉试验”的顺序。

> 最新交付要求：输出质量对标游戏买量素材，完整标准见 [买量素材质量与制作方案](GAME_AD_CREATIVE_QUALITY.md)。本文的高光检索与两周计划属于上游工程里程碑；找到片段和成功导出尚不代表广告创意交付完成。

## 1. 产品决策

**立即把“看画面找高光”设为新增能力主线，首个场景是无字幕游戏录屏。**

检索模块体验：导入游戏录屏 → 选择“通关 / 失败 / 险胜 / 自定义目标” → 返回带证据和时间段的候选 → 预览、调整、导出。字幕变为可选信息，不再是分析前提。完整产品在此基础上还需完成钩子、玩法表达、节奏、声音、结尾与变体制作。

先建立 Seed 单模型闭环，随后在同一组素材上比较 Jev 是否改善排序成本、速度或结果。不等待 Jev 访问权限，也不把监控、自动更新、账号建设作为视觉原型的前置条件；安装、隐私提示、现有功能回归仍是发布要求。

## 2. 模型核实与分工

### Seed Pro：画面理解与事件定位

字节官方确认 Seed2.0 Pro 具备多模态理解、时序与运动理解能力，系列 API 通过火山引擎提供。这支持将其列为首个视觉理解候选，不代表已经证明游戏高光定位质量。[Seed 官方介绍](https://seed.bytedance.com/en/seed2)

火山官方发布记录中已有 `doubao-seed-2-0-pro-260215`；LAS 文档也出现较新的 `doubao-seed-2-1-pro-260915` 支持记录。实施时以账号实际可调用版本、所在服务和官方接口说明为准；LAS 算子参数不能直接套进方舟原始模型接口。[模型发布记录](https://docs.volcengine.com/docs/ark/model-release-announcement?lang=zh)、[LAS 更新记录](https://docs.volcengine.com/docs/LakeAIService/VisualContentUnderstandingDoubao-15-vision-pro-32k?lang=zh)

首轮只跑一个可用的 Pro 版本作为质量基线，模型 ID 可配置。之后才比较 Lite 或其他较轻模型做初筛。不能把某个 Lite 版本的音频能力自动推定到 Pro；画面、声音、字幕三种输入分别做能力测试。

### Jev：可选的快速决策层

已找到与用户描述相符的 TypeSafe Jev：官方于 2026-09-15 宣布 early access。其当前文档明确只接受文本及文本化结构状态，不支持图像、音频或视频；对中文等 CJK 语言的准确度低于主要训练语言英语。这里按该模型研究；若用户另有所指，再替换这一实验。[官方发布](https://typesafe.ai/blog/introducing-system-one-models-and-jev)、[输入限制](https://docs.typesafe.ai/concepts/state)

Jev 的合适输入是 Seed 已生成的事件描述、字幕片段、OCR 结果或可取得的游戏状态，不是 MP4。可拆成三类问题：

| 类型 | 在 AutoClip 中拟验证的问题 | 代码如何使用 |
| --- | --- | --- |
| Choice | 事件主要属于通关、失败、险胜、普通操作还是未知 | 分类展示；保留未知选项 |
| Score | 与用户目标匹配程度、事件完整性、可观看性分别处于哪档 | 按明确标准组合排序 |
| Noul | 当前证据是否足以确认发生了用户指定事件 | 作为复看信号，不直接当精彩程度 |

同一候选的独立问题合并请求；后一个问题依赖前一个结果时再分轮。Noul 返回的是肯定概率，没有单独 confidence；Score 的数值也不能直接当作“正确概率”。[官方问题类型](https://docs.typesafe.ai/primitives)

类型正确不保证语义判断正确。官方延迟、费用和倍数比较是其特定工作负载的结果，不能等比例宣传成 AutoClip 加速。Jev 没有收到画面事实时也不能补回漏检，不能作为独立视觉验证器。

## 3. 第一版与后续架构

### 第一版：先让无字幕游戏能够出片

```text
本地视频 + 用户目标
  → 检查时长与格式，切成带绝对时间偏移的重叠窗口
  → Seed Pro 分析窗口，输出事件与证据
  → 校验时间、合并重复候选、排序
  → 用户预览并调整
  → 复用现有本地 FFmpeg 导出
```

初始工程假设：素材上限 3 分钟；窗口约 20–30 秒、相邻重叠 3–5 秒；最多展示 5 个候选。它们是实验配置，需依据漏检和成本调整，不是模型官方限制。

每个窗口都应有基本覆盖。比较 1 fps 与接口实际允许的更密采样，不将“粗采样没发现”判定为“没有事件”。视频输入仍可能在服务端抽帧；要保存实际请求参数与已知重采样限制。短于采样间隔的事件是专门的失败样本。

官方 ADK 文档提供 Files API 视频输入与 fps 控制的路径，可作为接入调研起点；最终用所选方舟接口做最小能力测试，不为调用一个模型引入整套 Agent 框架。[火山 ADK 视频输入说明](https://volcengine.github.io/veadk-python/cn/docs/framework/agent/responses-api/)

### 第二版：缓存事件，再快速搜索

```text
首次分析 → 缓存带时间与证据的事件索引
再次查询 → 文本/标签召回 → Jev 可选排序 → 必要时 Seed 回看 → 导出
```

首先用本地 JSON/SQLite 存事件描述、标签和时间，不立即搭向量数据库。同素材多次查询才是最可能体现 Jev 价值的路径：避免重复读取视频，快速重排已经看过的事件。

缓存必须包含素材内容指纹、窗口、模型版本、提示词版本、采样设置、索引覆盖范围。查询相关结果另外包含 query 与评分规则版本；修改目标不能盲用旧排序。

首次按“通关”分析出来的候选不能被当作完整视频索引。新问题超出描述粒度或索引范围时重新看原片，明确“未检索到”与“确认不存在”的区别。

### 第三版：有证据再加更多召回信号

按漏检原因选择 OCR、音频峰值、镜头变化、运动变化、文本/视频 embedding 中的一项。它们提供候选线索；例如背景音乐变响不等于高光，游戏 HUD 闪烁也不等于成功。

用多个信号取并集后再复看，并保留全覆盖采样基线，防止候选筛选过早丢失事件。视频 embedding 属于相似检索能力，Jev 属于判断能力，两者不能混为一谈。

## 4. 游戏场景顺序

| 顺序 | 场景与用户目标 | 关键证据 | 首期难点 |
| --- | --- | --- | --- |
| 1 | 超休闲/闯关：失败、成功、连续奖励 | 状态变化、结算画面、奖励计数、动作结果 | 失败后的重开与结算重复，不重复切同一事件 |
| 2 | 动作/竞速：险胜、躲避、反超 | 危险前状态、动作过程、成功结果 | 快动作容易漏采；“险些”需前后连续证据 |
| 3 | FPS/MOBA：连杀、残血反杀、团战 | 击杀提示、血量、阵营与结果 | 游戏规则、HUD、第一/第三视角差异 |
| 4 | 扩展到体育、宠物、操作演示 | 相应领域的事件定义与完整过程 | 每个新场景独立加样本和判定规则 |

首版选一种实际有素材的游戏，默认从超休闲/闯关开始。输出保留“铺垫—关键动作—结果”，而不只截取结算帧；前后保留长度依据事件调整。最初使用原画比例或完整画面适配，竖屏时不默认中心裁切导致 HUD、角色或目标丢失。

不要求游戏内部埋点才能处理已有录屏。若后续能取得可信游戏状态，可作为独立增强输入，记录来源，不将推测血量当作真实遥测。

## 5. 现有代码中的接入点

以下为当前工作区静态检查结果。实现需在最新发布基线复核。

| 位置 | 当前边界 | 最小修改方向 |
| --- | --- | --- |
| `backend/core/llm_providers.py` | 主要将输入拼为字符串，调用文本接口 | 新增显式视觉适配器与能力标记；不能只新增一个模型名 |
| `backend/services/simple_pipeline_adapter.py` | 从字幕或自动转写进入 outline / timeline / scoring | 在字幕检查前按 `pipeline_mode=text/visual` 分支；visual 不强制转写 |
| `backend/pipeline/step2_timeline.py` | 依赖 SRT 分块和大纲文件 | 视觉分支独立生成候选；不伪造空 SRT 以通过旧步骤 |
| `backend/pipeline/step6_video.py` | 根据带标题及起止时间的候选切片 | 通过转换层复用，检查必填 id、时间格式与元数据 |
| `backend/models/clip.py`、`backend/schemas/clip.py`、`backend/services/clip_service.py` | 创建/返回有整数秒字段和 `int()` 转换 | 保留亚秒时间并统一预览/导出；修改需兼容已有数据 |
| `backend/services/publish_export.py` | 已有重编码与画幅处理；有裁切型预设 | 复用原画/完整画面布局，校验无字幕路径和 HUD 完整性 |
| `backend/eval/metrics.py` | 主要检查片数、长度与覆盖 | 新增事件召回、Top-K、边界与重复率；无高光样本允许零结果 |

建议新增小模块：`visual_client`（模型与媒体输入）、`visual_windows`（采样/偏移）、`highlight_candidates`（校验与合并）、`highlight_ranker`（基础排序/Jev）。具体目录随最新基线确定，不先重构所有提供商。

候选内部契约草案：

```json
{
  "candidate_id": "event-001",
  "start_sec": 12.25,
  "peak_sec": 15.50,
  "end_sec": 19.10,
  "event_type": "level_failure",
  "summary": "角色碰撞障碍后进入失败结算",
  "evidence": [{"at_sec": 15.50, "source": "vision", "observation": "碰撞后出现失败画面"}],
  "uncertainty": "碰撞前的精细动作可能受采样影响",
  "window_id": "window-000",
  "ranker": "seed_baseline"
}
```

上面是说明性假数据。时间全部转换成原视频绝对秒数，保留小数；必须满足 `0 <= start <= peak <= end <= duration` 且 end > start。模型先给相对时间时由代码加窗口偏移，并验证窗口边界。重叠窗口去重不等于合并两个相邻但不同的事件。

没有字幕时不套用旧字幕吸附规则，不为达到最少片数强行补“高光”。所有低置信度候选可保留为待确认；无匹配、解析失败、调用失败分别记录。

## 6. Jev 必须通过的对照实验

第一阶段先保存同一批 Seed 候选，比较：A）Seed 返回的排序；B）确定性规则排序；C）Jev 多维评分。保持候选集合不变，避免把采样变化误算成 Jev 收益。

第二阶段再比较完整路径：Pro 全流程、较轻模型提取 + Pro 复看、事件缓存 + Jev 重排。较轻模型只有在候选召回过关后才能替代 Pro 初筛。

Jev 同时测中文原始事件和英文结构字段/描述；若翻译需要额外模型，其费用、时间和语义损失必须纳入。首版不默认把中文用户内容悄悄改为英文来美化结果。

Jev 异常或无访问权限时用基线排序，保留候选。它先作为旁路打分，不直接过滤内容；有标注证明阈值可靠后再考虑自动筛除。

成本与时间按整条链记录：上传 + 解码/采样 + 视觉提取 + 排序 + 复看 + 导出；首次索引与第二次检索分开。排序若只占总耗时 10%，即使它快十倍，整条链理论也只快约 1.10 倍，必须优化真实瓶颈。

## 7. 最小评测集与验收

第一轮用 3 条自有/授权短录屏：明确成功、明确失败、没有高光。第二轮扩到至少 10 条，包含快事件、跨窗口事件、重复结算、遮挡、HUD 误导、低帧率和无音频。以不同录屏/局次分开发集与留出集，同一原片的相邻窗口不能分到两边。

人工为每条素材标事件类型、关键时刻、可接受的起止范围；允许多个合理剪法。每条样本至少两个目标，包含目标不存在的查询。

| 指标 | 定义 | 初始目标或决策 |
| --- | --- | --- |
| 事件召回 | 标注事件中，有候选覆盖关键时刻且类型正确的比例；每条视频最多 5 个候选 | 首轮目标 ≥80%，同时看逐类错误和小样本计数 |
| Precision@3 | 前 3 个候选里真正匹配目标的比例；不足 3 个分母按 3，另报返回数 | 有高光查询的平均目标 ≥2/3 |
| 无高光误报 | 无匹配查询中输出错误高光的比例 | 单独报告，不能被正样本指标掩盖 |
| 边界 | 起止落入人工接受范围，且保留事件完整过程 | 至少 8/10 抽查片段无需修边界；模型时间戳不等于帧精确 |
| 重复率 | Top-K 中重复描述同一事件的数量 / 返回数 | 去重后单个事件不占多个推荐位 |
| 效率与费用 | 每视频分钟耗时/费用、首次结果等待、人工修正时间、缓存命中 | 初期全部实测；小样本列中位数与范围，不夸大 p95 |
| Jev 增益 | 固定候选集对比规则与 Seed 排序；单独记录阶段和端到端成本 | 检索质量不明显退步，并且费用/延迟或质量有实际收益才默认启用 |

上述为内部验收起点，不构成性能保证。召回的宽窗口取巧用边界和人工可用性检查约束。预算上限在首次调用前按账号价格和样本长度设置；未知费用记录未知，不显示为零。

## 8. 接下来两周的具体顺序

预算延续每周 5–10 小时，约 70% 用于多模态、20% 必要集成与回归、10% 案例；只处理阻塞本次交付的基础问题。

1. **前 1–2 个开发时段**：确认模型权限、所选接口视频输入和返回格式；准备 3 条素材；建立 Seed 直出候选的可复现脚本。凭据与素材就绪后争取 72 小时内拿到首次结果，不承诺此时已是桌面功能。
2. **第 1 周目标**：候选通过时间校验，可从无字幕视频导出一条可用游戏片段；保存结果与失败样本，形成 A 基线。
3. **第 2 周目标**：接入最小“按画面找高光”入口、预览与导出；验证 Windows/Mac 范围内实际可用的包；Jev 有权限则用保存候选做对照，无权限则完成规则对照。
4. **第 3–4 周**：优先修漏检和边界；缓存事件支持同素材不同查询；根据实验决定 Jev 是否进入默认路径。
5. **第 5–6 周**：以明确事件模板扩一个新游戏类型或一个新场景，逐场景公布支持范围；不承诺任意游戏。

第一周未跑通模型或候选定位，则第二周继续此项，UI 顺延；不会转回四周基础设施建设。即使 Jev 没有证明增益，Seed 游戏高光仍可独立交付。

媒体使用边界：模型分析可能上传画面/视频，调用前清楚展示；只发送用户选择素材，日志不记录密钥与私有媒体地址。缓存清理、远端媒体生命周期和重试费用归入视觉任务实现。当前研究没有读取凭据或上传任何素材。
