# AutoClip 1.4 统一体验与效果优化排期

2026-09-22。用户明确要求：游戏素材和原高光/内容切片，在输入、剪辑和发布导出体验上保持一致连贯；游戏能力融入现有产品，不另设全新产品链路。六款v6模板作为首期基准，动效字幕继续后置。

## 产品原则

用户面对一条流程：**导入视频 → 快速识别并勾选建议类型 → 用户确认 → 正式理解与剪辑 → 调整镜头和包装 → 预览 → 导出/下载。**

内容理解与视觉理解是后台分析方式，前台只在必要位置呈现素材/创作选项。同一份素材、同一个项目、同一编辑器和成片版本；切片和合集也能进入同一工作区。无需用户理解Studio、模型路由或打开外部工具。已有视频保留直接下载，不强制重渲染或迁移历史数据。

“发布”本期先统一已有导出/下载体验，不把平台自动投稿、广告账户投放或投放数据回传算作已经实现，也不为收口临时新增这套能力。

## 9/22 最新交互实现

统一链接/文件表单已替换三种制作方式的前置 tab。导入只抽取 4 张低分辨率画面做快速判断，随后停在独立导入确认页：内容切片 / 精彩高光 / 推广成片可多选；自动勾选建议项，用户可取消或补选。时长、语言和画幅自动匹配，可选修改折叠。未确认素材只在“未完成的导入”保留，不进入正式项目列表。仅显式点击“确认并开始制作”才进入项目页并触发正式理解与剪辑；刷新、重启和返回首页不触发制作。识别失败不伪造推荐，保留人工选择。

接口与验证说明见 [智能导入确认流程](SMART_IMPORT.md)。以下旧审计保留为差异基线，下游结果与导出统一仍按原排期推进。

## 此前产品状态（改造基线）

基于 `83b6d7c9`，在本机8780启动真实应用工厂与当前前端生产构建，使用复制的隔离数据库。游戏项目来自历史真实Seed联调；旧切片项目明确标为手工兼容样本，仅用来检查旧卡片与编辑入口，不是旧算法评测证据。

- 首页同一导入区域提供“内容切片 / 精彩高光 / 推广成片”，但切换后仍是不同表单组件，字段和行为未完全一致。
- 项目页已经共用 `/project/:id` 和“你的成片”区域，但旧切片/合集卡与视觉草稿卡的按钮、状态、预览和文字密度仍不同。
- 旧切片/合集可创建草稿进入 `/project/:id/studio/:draftId`，游戏草稿也用这个编辑器；桥接已存在，无需再建独立游戏编辑页。
- 旧切片有自己的直接导出弹窗；新草稿使用成片导出与历史记录，尚未完全汇合。
- 旧任务进度与视觉分析阶段提示不同；“成片”区域目前混放可下载视频和未渲染草稿，需要清楚显示状态。
- 游戏源预览不完整模拟最终剪辑；实际渲染预览已可使用，应强化状态区分。
- 浏览器本轮实际完成：游戏草稿选择漫画v6 → 保存V7 → 点击渲染预览 → 后台完成 → 切换实际渲染结果。同时点击旧切片“预览与制作”，确认真实跳入同一成片编辑器。没有重新调用模型；不代表从新素材起的完整真实AI回归。

## 实施顺序与检查点

1. 从 `CreativeImport` 和旧 `FileUpload/BilibiliDownload` 提取共同输入状态与表单，保留各自提交适配；检查文件、URL、字幕、Cookie和配置缺失行为。
2. 将旧clip/collection和visual draft适配为可展示的结果对象，统一主操作；保留独有的信息但折叠显示。明确“待编辑 / 待渲染 / 渲染中 / 可下载 / 失败”，不把草稿生成成功显示成视频已经生成。
3. 将编辑后的输出接入共同导出体验；不要只将两个旧弹窗换名。历史下载和版本数据应可验证地保留。
4. 在共同流程稳定后调整自动选段和创意结构，六款模板复用既定渲染；普通字幕缺失要提前说明，ASR自动识别是否纳入首发按实际工作量明确，卡拉OK不纳入。
5. 对前后两种来源做同操作步骤的真实浏览器回归，记录实际点击和输出结果，再做整片视觉/声音复看。
