## 2. 用户真正拿到什么

输入一个或多个同游戏链接/录屏，以及推广哪款游戏、受众、语言、渠道和可用品牌素材。首次可采用待确认的简报默认值做研究预览；正式导出必须对应明确产品。不同游戏自动分组。

输出一个创意包：

- 一条 15–30 秒左右、可进入人工投放评审的主片，长度按镜头和创意确定。
- 同一主体的两个开头变体，分别说明想测试什么。
- 预览、MP4、可编辑方案、原片证据、质量报告及待补录清单。
- 每条创意的独立 ID，便于投放数据回流。

产品交互以“创意卡片”为中心：一句话卖点、为何选这些镜头、预计效果假设、可换钩子、可改文字/声音、可预览。技术上的抽帧率、模型路由、HTML 等放到内部执行层。

## 3. 制作流水线

```text
链接/录屏 + 创意简报 + 效果参考
  → 素材接入：按游戏分组、媒体探测、有效画面区域
  → Seed 粗看全片：玩法、场景、事件候选、无用区间
  → Seed 精看候选：目标—动作—结果、时间边界、可用构图
  → 证据素材库：片段角色、前后关系、缺失信息
  → 创意规划：提出 3 个方向，选择证据最完整的 1 个
  → 编辑方案：源片段 + 成片时间 + 构图 + 文字 + 声音
  → FFmpeg 预处理 + HyperFrames 合成与渲染
  → 成片视觉/声音复看 + 规则检查 + 人工验收
  → 一主两变体 → 同条件投放测试 → 迭代
```

### 素材接入与两遍理解

链接先记录为来源，媒体处理复用现有下载/本地导入能力；下载不可用时状态明确保留，不让网页标题替代实际画面。用于实际投放的资产需记录来源和可用范围。第三条链接的末尾中文分号已去除。

先探测分辨率、帧率、时长、声轨和黑边/背景。第三条必须区分“文件画布”和“实际游戏画布”；第二条的横版也不能直接默认中心裁切安全。

粗看先建立全片地图，按场景和玩法连续性分段，保留窗口重叠；用低频抽样控制成本，快速运动处增加覆盖。抽样率、分段长度依据实际 API 限制和漏检测试设定，不先固定成万能参数。

精看只处理候选及其前后文，快速跑酷需要连续短片或更密采样，避免只看几张截图就推断“差点撞上”。局部时间统一映射至原片绝对时间；边界由视频与帧定位核验，ASR/OCR 仅作辅助。纯游戏没有台词也必须可以完成。

每个事件记录：源文件、游戏/局次、起止、前置目标、动作、结果、可作钩子/解释/升级/收尾的角色、可见证据、主体/障碍/HUD 区域、缺失项与置信度。数据模型保存浮点秒或有理时间，避免现有整秒截断。

### 创意选择要有目标和反证

模型对每个方向回答：观众为什么停下？能否看懂自己可以做什么？为什么愿意尝试？原片能否兑现承诺？哪段必须保留，哪段只是重复？

门槛先于分数：没有对应目标、结果、真实因果或安全构图的概念直接退回。通过门槛后，按目标清晰、期待感、推进、反馈、可读性和证据完整性排序；附理由与缺口。分数只表示制作判断，不叫“起量概率”。

Jev 可以在已验证的文本事件上帮助排重、分类与候选比较；首轮先用规则/Seed 建基线。Jev 不看原片，也不判定真实广告回收。技术边界沿用[模型接入计划](MULTIMODAL_HIGHLIGHTS_PLAN.md)。

## 4. 跑酷首条样片的具体提案

创意主张：**一段观众能看懂并预判下一步的连续避障。** 不预设已经找到了某个失败、连躲三次或最终奖励；先精读原片找完整证据。以下时间全部是成片节奏草案。

| 成片区间 | 画面目的 | 检索条件 | 制作处理 |
| --- | --- | --- | --- |
| 0–2 秒 | 立刻看见一个将要发生的选择 | 主角、障碍、可选路线同屏，结果尚未揭晓 | 快速进入实际玩法；可加“这一步往哪躲？”等与画面相符的短文案 |
| 2–7 秒 | 让观众理解动作规则 | 同一段连续操作，选择与结果能对应 | 首次关键操作尽量原速，必要时一次短暂提示 |
| 7–14 秒 | 提升期待 | 障碍更密或动作组合更复杂；如原片不存在则缩短 | 减少无事路程，保持每次关键动作的前因后果 |
| 14–18 秒 | 兑现一个结果 | 真实通过、奖励或失败中的一种 | 保留反馈及游戏音；没有失败不编造失败字幕 |
| 18–21 秒 | 给出下一步 | 对应实际游戏和下载入口 | 简短 CTA；不能用无依据的胜率/排名宣传 |

第一轮三个版本只改变开头表达，尽量保持主体、长度、受众和声音条件一致：A 直接进入玩法；B 同画面加问题文案；C 同画面加一句解说。若同时换画面、BGM 和节奏，就无法知道胜出原因。

如有真实失败与紧接着的重试，可另做“这次能过去吗”的第二概念。不要跨局拼成假连续通关。若原片缺少可读的开头或明确反馈，输出需要补录的起始状态、动作和结局；优先补足内容。

## 5. 另外两类素材的创作方式

**驾驶。** 先确认推广的游戏身份，再寻找一段明确驾驶目的和操作反馈。车辆选择、路线挑战、操控体验是候选方向。摩托与汽车可用于明确标示的玩法展示，但不能剪成同一次驾驶无故变车。平路行驶、菜单、重复绕路通常不应承担主钩子。未核对完整原片前，不宣称已有跳跃/漂移/撞车片段。

**合成。** 找到一个可读的需求或目标，选择生成/合成/升级到兑现的一条因果链。物品太小则用局部特写解释一次，再回到能看懂目标的全局；可删等待但保留关键状态变化。若只找到整理棋盘，也可以做解压方向，不能将其包装成已完成订单。标题中的活动名称不证明素材里有戏剧故事，不能凭游戏 IP 自动添加“救母女”等不存在剧情。

三类都要区分：从原片挑选、重组和视听包装；需要新录屏才能实现的创意；需要另行制作的新叙事/生成镜头。模型明确指出内容上限。

## 6. HyperFrames 的位置与接入方式

已研究 [HyperFrames 官方项目](https://github.com/heygen-com/hyperframes)及[官方介绍](https://hyperframes.heygen.com/introduction)。它能把 HTML/CSS、媒体和动画渲染成可编辑、可重复输出的视频项目，适合本任务的文字、局部强调、版式、音轨和尾卡层。它不替代游戏理解，也没有证据表明使用这个渲染器本身会提升 CPI 或 ROAS。

首轮建议：FFmpeg 处理媒体探测、代理素材、必要片段预处理；HyperFrames 负责整片合成与最终渲染。为每一种处理指定唯一执行者，避免裁切/变速在两层重复应用。现有 FFmpeg 导出保留为基础版本，先验证一条片再决定集成深度。

官方 skill 的适配入口是 `hyperframes → general-video`（已有素材重组），按需使用 core、keyframes、audio、media-use、cli；不是把游戏录屏套成网站宣传页。已安装并执行 general-video 工作流，实际完成三条本地样片。[官方路由说明](https://raw.githubusercontent.com/heygen-com/hyperframes/main/skills/hyperframes/SKILL.md)

建议为 AutoClip 增加独立 renderer adapter：内部编辑方案稳定，输出可以选择基础 FFmpeg 或 HyperFrames，避免供应商格式成为业务唯一存储。

| AutoClip 编辑字段 | HyperFrames 映射/处理 |
| --- | --- |
| 源片段入点 | `data-media-start` |
| 成片开始时间 / 成片持续时间 | `data-start` / `data-duration` |
| 恒定速度 | `data-playback-rate`；消耗源时长 = 成片时长 × 速度 |
| 构图/缩放 | 内层视觉容器的可定位动画；保留动作与目标区域 |
| 原声、旁白、BGM | 显式音轨与一致时间映射，避免原声重复混入 |
| 字幕/注释/尾卡 | 独立图层与时间范围；不得遮住关键操作 |

字段与时间计算参考[官方剪辑配方](https://raw.githubusercontent.com/heygen-com/hyperframes/main/skills/hyperframes-core/references/creator-editing-recipes.md)。本表是设计映射，不是已通过渲染测试的实现。接入时固定版本和依赖、使用本地资产与字体、检查真实导出结果。

## 7. 验收与“起量”验证

先验收成片：逐镜头回溯源片；关键动作不被裁切；小屏可读；无黑帧、断音、重复音轨和错误字幕；实际渲染后复看完整视频。HyperFrames 的结构检查通过，只能证明工程合规，仍需内容与视听检查。

第一条片用同素材人工版本做盲评，记录制作时间、修改时间和退回原因。达到人工测试门槛才进入投放。三条 YouTube 原片的自然播放量不作为买量有效标签。

投放按渠道/地区/系统/受众/时间/归因窗口分组；首轮测试一个开头变量。先看观看与点击作为诊断，再看 CPI/IPM 及安装后留存或 ROAS。用足够样本和不确定性判断，预先设置预算/停止条件，不能按一天 CTR 冠军宣布成功。实际预算和目标尚未指定，本次不投放。

有结果后按 `creative_id → concept_id → hook_version → edit_spec → source_event_ids` 追溯原因。在相同原片与创意条件下比较开头，才能逐渐知道哪些结构在什么人群上有用；不能只用模型主观评分循环优化。

## 8. 开发顺序与本轮交付边界

1. 以跑酷输入完成全片事件清单与候选精看，选出一个有完整证据的概念。
2. 用该概念做一条人工参与的可编辑样片，验证横转竖、文字与音轨；初版可保留横屏玩法画幅嵌入竖屏布局，优先确保全部路线可见。
3. 打通统一编辑方案到 HyperFrames 的适配和成片复看，再输出两个开头变体。
4. 用 Gossip Harbor 验证有效画面裁切与合成因果链，再扩驾驶。
5. 在质量基线稳定后比较 Jev 的效率收益，并在获得真实投放结果后更新 Golden 库。

本轮已完成输入抽查、创意与架构设计及三条本地开头变体；尚未验证投放效果。下一实施里程碑是可配置语言/字幕的 AutoClip 应用内制作与导出，不要求用户打开 Studio。
