# 统一成片工作区（首版）

分支：`codex/visual-game-ads`。实现基于已确认的统一界面方案，保留原内容切片和合集功能。

## 用户流程

1. 首页选择链接/文件与内容切片、精彩高光或推广成片。游戏模式将时长、文字语言、画幅折叠到更多设置。
2. 项目页集中显示成片草稿与原切片、合集。分析过程在页内显示，原素材与候选事件按需展开。
3. 打开成片后可以修改名称、开头文字、输出语言、原声、字幕、画幅、构图以及镜头顺序和起止点。文案建议确认后应用，可撤销。
4. 导出在弹窗确认，后台用 FFmpeg 渲染，实际结果可预览和下载；导出记录跨页面保留，无需启动 HyperFrames Studio。

## 视觉模型设置

进入「设置 → 视觉理解」，填写 OpenAI 兼容的图片 Chat Completions 接口根地址、API Key 与模型/推理接入点 ID；可设置 10–300 秒超时。

测试连接会发送一张内置红色图片并校验识别结果，不发送项目素材。测试和保存分开；密钥不回显，留空保留，明确勾选才清除。配置保存在当前数据目录的 `vision-settings.json`，写入文件权限为 0600，与文本模型设置独立。

未保存配置时兼容 `.env` / 进程环境变量 `AUTOCLIP_VISION_BASE_URL`、`AUTOCLIP_VISION_API_KEY`、`AUTOCLIP_VISION_MODEL`，以及现有 `SEEDANCE_BASE_URL`、`SEEDANCE_API_KEY`。已保存的界面配置优先，包括主动清除密钥的情况。

## 数据与模块

- `backend/services/studio/` 分离配置、模型、原子存储、视觉分析、任务和渲染。
- `backend/api/v1/studio.py` 提供 `/api/v1/studio` 接口。
- `frontend/src/features/studio/` 负责导入、结果、编辑、导出记录与视觉设置。
- 项目草稿、事件与导出记录存放在 `projects/<id>/metadata/studio.json`，视频输出按任务 ID 存在 `output/studio/`。
- 旧切片/合集按来源顺序转成独立草稿，不修改旧视频和元数据。草稿用版本检查拒绝陈旧保存，浏览器暂存未保存修改。
- 每次导出记录不可变的草稿快照，运行中的重复请求去重；进程重启后的未完成任务显示失败并允许重试。

## 明确边界

视觉理解采用有时间戳的静帧初筛，最多 60 帧；对第一候选最多追加 25 帧复核。当前限定原素材 1 秒至 2 小时，每段成片最多 30 分钟。它可能漏掉短暂动作，时间边界和玩法仍需看原片确认。

推广模式首版复用同一事件生成不同开头；不包含自动补拍、配音、音乐、动态包装或完整时间线编辑。语言设置翻译开头文字与已有字幕；无字幕时明确提示，不会伪造转写。AI 修改当前仅针对文案。

桌面任务使用进程内线程池，适用于本地单进程运行；尚未提供多进程分布式调度或断点续跑。真实广告投放效果、Golden Case 评测闭环以及完整动作模型检索仍需后续迭代验证。
