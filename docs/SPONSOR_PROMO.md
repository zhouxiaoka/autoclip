# 赞助推广的签名配置

这是给维护者的发布说明，不是已经上线的服务。客户端默认不请求任何地址。

## 已发布客户端

v1.5.8 和当前 RC（`8fb72a745d8080225e371d60ee325f5431b6e195`）的服务商目录都只读安装包里的 `backend/presets/provider_presets.json`。`backend/core/provider_presets.py` 写明远程拉取不在目录加载器的范围内。功能开关只控制实验功能，不改赞助列表、顺序或默认项。

因此已安装的 v1.5.8 不能消费这份新配置。要让用户看到远程推广，需要一次带有该客户端的升级。不能指望旧版本自己改掉。

## 这份配置能改什么

只改新用户选择器里的展示：

- 安装包当前推广的内置赞助商的名字和顺序（`apimart`）
- `api88` 和 `infistar` 不在安装包推广、README 或默认选择里。客户端仍信任它们原来的注册主机（`88api.ai`、`www.infistar.cc`）。更高序号的有效签名可以按这个主机把其中任意一个重新放进选择、重排或设为默认，之后再用更高序号撤回成中性。未知服务商和新的注册主机一律拒绝
- 已保存服务商的状态通知，包括当前没有推广的 `infistar` 和 `api88`
- 新用户默认推荐哪一个
- 状态：`healthy`、`fault`、`out_of_service`
- 八种界面语言的短通知
- 可选的语言分流（`locales`）：限制某个赞助商只在指定界面语言下进入新用户推荐（如 `["zh"]` vs `["en", "ja", "ko", "es", "fr", "pt", "ru"]`）；允许不同语言分组各自指定一个 `new_user_default: true`，但在任意同一语言内至多只能有一个默认项
- 同一注册主机名下的注册链接（`register_url` 或按语言区分的 `register_urls` 映射，同样严格校验 HTTPS 与已信任主机名）

`out_of_service` 只从新用户选择器里隐藏。`fault` 仍显示，并带通知。

它不能改已经保存的服务商、密钥、接口地址、项目，也不能改模型路由、分析任务，或引入目录里没有的接口。

## 信任边界

公钥和 URL 只写在安装包的 `backend/presets/sponsor_promo_config.json`。远程文件不能更换这两项。三者缺一（`enabled`、`https` URL、32 字节公钥）时，客户端不发起请求，选择器使用安装包内的顺序。

当前仓库已指向独立的 Cloudflare Worker 静态分发地址（与诊断服务完全隔离），公钥写在 `backend/presets/sponsor_promo_config.json`，私钥仅保存在维护者本机仓库外并备份到密码管理器。测试用的密钥仍在测试进程里临时生成，不接触生产私钥。

生产静态文件地址：

`https://autoclip-sponsor-promo.autoclip-val-3f71ee83.workers.dev/sponsor-promo.json`

只放这一个 JSON。签名在文件内部，不跟随跳转。TLS 负责传输，Ed25519 负责内容。私钥留在维护者自己的密码管理器里，不进仓库、不进客户端、不进日志。

## 签名和回滚

```bash
python scripts/sponsor_promo_sign.py generate --private-key ~/secrets/autoclip-sponsor.pem
python scripts/sponsor_promo_sign.py sign --private-key ~/secrets/autoclip-sponsor.pem \
  --payload promo.json --out envelope.json
```

第一条命令用 `O_CREAT|O_EXCL` 和 `0600` 创建私钥，拒绝已存在的文件和符号链接。私钥只放在仓库外的目录，并另外备份到密码管理器。轮换公钥必须发一个新的客户端版本：安装包里的公钥是信任根，远程文件不能换钥匙。私钥如果泄露，停止用它签名，把 `min_sequence` 提到已发出的最大序号以上，并在下一版客户端里换一把新公钥。不要在仓库或 CI 里生成生产私钥。

`sequence` 必须大于客户端已经接受的最高序号。相同序号只有在签名和内容摘要与已接受的那一份完全一致时，才用来补写损坏的状态文件；换一份同序号内容会被拒绝。更低的序号一律拒绝。

要撤回一份坏配置，用更高的新序号重新发布之前的内容。安全历史先写入 `sponsor-promo-checkpoint.json`，再写主文件和备份。每一份都先 `fsync` 文件再替换，然后 `fsync` 目录。展示过期不会把历史清成 0，也不会把过期内容显示出来。主文件缺失时用检查点或与它一致的备份，不会把水位当成 0。更旧的备份不能把已经提交过的水位降下来，也不能因此接受一个介于两者之间的序号。检查点、主文件和备份都损坏或无法读取时，拒绝新的推广而不是从 0 重新开始。三份文件连同检查点一起被删掉，和从未写入过无法区分，这不是磁盘信任根。`fault` 仍可出现在新用户推荐里并保留通知。`out_of_service` 和从推荐名单移除的赞助商不再进入新用户推荐，已保存的连接仍可编辑。

新鲜安装还没缓存时，攻击者若能换掉静态文件，仍可能让它第一次拿到一份旧但签名有效的文件。下一版客户端把 `min_sequence` 调到坏序号以上，可以从安装包一侧封死那些旧文件。

过期、签名不对、版本不在 `min_app`/`max_app` 之间、超限、非 200、发生跳转，都丢弃这次响应。还有未过期的上次成功结果就继续用它，否则回到安装包顺序。

桌面端在启动后、打开设置时，以及空闲周期（默认 6 小时）请求 `GET /settings/sponsor-promo`。这次请求先返回当前已接受的内容。结果仍 pending 时，当前这个界面保留一次 `after` + `wait`（服务端最多等 3 秒）。返回太快就等 250 毫秒再问，避免空转。同一时刻只有一个等待，宿主卸载就停。生成任务占用时不发起外网请求；最后一个任务结束会自己补拉，正在显示的界面在下一次等待里看到结果，不必重新打开，也不必等到 6 小时。未配置时这次请求只返回安装包顺序，不会访问外网。通知保留全部语言，界面按当前语言显示。`fault` 和 `out_of_service` 会显示在实际启用的分析、画面、封面和云端转写上，不改密钥、地址或正在跑的任务。`out_of_service` 不再出现在推荐或注册入口。`api88` 和 `infistar` 可以出现在状态里。安装包默认不推广它们；只有更高序号、且注册主机仍是原来已信任的那一个，才能把它们放回推广，再撤回。已保存的密钥、接口地址和任务不改。
