# 自定义模型请求设置

在 **设置 → 服务商与模型 → 添加自定义服务商**（或已有自定义连接的配置页面）展开 **高级请求设置**。

三个字段均为可选；不配置时保留现有请求行为。配置属于这一服务连接，不会传给其他连接。

- **HTTP Headers（JSON）**：字符串键值对，例如 `{"X-Workspace": "workspace-id"}`。用于模型列表获取、快速测试、试跑，以及正式文字/视觉请求。Header 可以补充服务商要求的认证字段；API Key 可留空。
- **推理强度**：选择服务商支持的 `reasoning_effort`。默认不发送该字段；不同服务商可能只支持部分取值。
- **附加请求参数（JSON）**：例如 `{"thinking": {"type": "enabled"}, "provider_options": {"mode": "balanced"}}`。对象在文字/视觉 Chat Completions 的 JSON 请求顶层合并，不是名为 `extra_body` 的嵌套字段。仅填写服务商支持的参数；不适用其他原生音频或图像协议。

高级参数也会用于快速测试和试跑，所以测试与正式调用不会使用两套配置。推理可能增加响应时间与费用；此功能不会自动发起真实模型调用，仍由用户的保存/测试/生成操作触发。

## 保存与安全边界

Header 值像 API Key 一样只保存在本地配置文件，不会出现在公开设置响应里。重新打开配置后，输入框留空代表保留已保存的 Header；输入 `{}` 或点清空会删除它们。修改服务地址后，需要重新填写 Header，避免把旧认证信息发送到新地址。Header 不是可分享的配置，请不要把真实值粘贴进 issue、PR 或日志。

Header 名称必须是有效的 HTTP token，值必须为可打印 ASCII 字符；拒绝换行、重复的大小写无关名称，以及 `Host`、`Content-Length`、`Transfer-Encoding` 等路由/报文控制字段。最多 32 个 Header，每个值最多 4096 字符。携带自定义 Header 的 SDK/视觉请求不会自动跟随重定向；模型列表和连接探测也不跟随重定向。

附加参数最多 64 个顶层字段、16 KB，且必须是有限值 JSON 对象。不能覆盖应用控制的模型、消息、流式行为、token 上限、响应格式或传输设置，也不能以附加参数覆盖单独选择的 `reasoning_effort`。这些约束保护自动分析的协议和重试预算。

旧配置无需迁移。没有新字段的连接继续按原逻辑工作；八种界面语言均有对应说明。
