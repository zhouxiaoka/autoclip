## 修复范围

从 v1.5.2 标签建立最小候选，仅带入 PR #263 的必要修复和回归：

- 访谈式竖屏视频遇到已标记完整画面保留的引用卡、幻灯片时，保留两侧内容；说话人镜头继续按人物取景。
- 补齐百炼 qwen3-vl-flash 及已核实快照的视觉能力；未知能力的模型可在设置中确认，不按任意模型名称猜测能力。
- 全局关闭画面识别后，自动封面选帧和硬字幕语言判断不向视觉服务发送素材画面；显式生成 AI 封面的授权仍独立处理。
- 视觉扫描与细化兼容模型直接返回事件对象列表，仍校验事件边界并拒绝混合列表、截断及其他错误格式。
- 包含 [1.5.2](RELEASE_1_5_2.md) 与 [1.5.1](RELEASE_1_5_1.md) 的必要热修，不带入主分支无关演示与文档改动。封面人物主体选择继续后续迭代。

## 复现与验证

四项问题均在最终 1.5.2 包的隔离环境或其实际素材流程中暴露，不能用同一版本替换安装包掩盖失败。已有修复前后回归覆盖画面切换、模型设置和路由、关闭画面识别的保留绑定、有效事件数组与错误回答。真实 FFmpeg 回归同时加入 Windows CI。

PR #263 的完整源码检查通过：1204 项后端测试通过，2 项有明确定义的跳过由专门 Windows/网络检查补充；223 项前端测试通过，全部 11 组门槛通过。真实视觉扫描及细化已返回有效候选，但这是源码补充证据，内容质量与最终安装包出片仍待验收。新候选会重新运行完整检查及标签构建。

缺口来自测试仅覆盖人物裁切、已知模型、正常 JSON 对象和分析主路线，没有追踪自动封面及字幕判断对保留视觉绑定的调用，也没有检查完整画面镜头的模板组合。新增回归直接覆盖上述边界；最终包仍须验证对应用户任务。

## 持续状态文件占用阻断

标签 v1.5.3 的 Desktop Build 37094900488 已完成，双平台包、安装运行时和升级检查通过，但随后补查发现：持续 Windows 文件共享冲突超过现有重试预算时，渲染任务本身结束，连记录失败的写入也被拒绝；同一后端实例读取旧状态仍为 queued。离线复现十次替换尝试、约 0.79 秒后仍排队，没有模型或遥测请求。这个复现证明同类缺陷，不能据此断言就是历史远端 PermissionError 的具体触发原因。

修复分支记录与项目路径关联的无内容终态补丁，让实际已失败的渲染、分析、准备和封面任务在读接口中可见；保留原持久文件、原素材及已完成成片。权限恢复后的显式重试写入终态并开始新的任务，不自动重放原业务操作。分析 flow 与已有成片保持，临时文件清理失败不覆盖原始异常，提示支持八种语言。

本地聚焦回归覆盖持续占用、读接口终态、释放权限后的重试、已完成成片/封面保留、分析/准备失败、拒绝新任务与数据目录隔离。PR #265 的运行时修复提交 68eed71ab9319bc141c0e7e6711bbe89553aaa54 已通过全部 11 组本地源码门槛（1213 项后端、223 项前端、2 项定义内跳过），聚焦状态恢复回归 15 项通过。真实 Windows 文件句柄占用等媒体回归 50 项通过，三项完整画面 FFmpeg 回归通过。新增多任务边界能拒绝先前修复逻辑，其他待处理成片不会因单条失败提前结束。Windows 初次测试的默认编码读取失败已通过明确 UTF-8 修正；应用读取本来使用 UTF-8。PR 其余阻断检查和最终安装包 GUI 复测仍待完成。**这些源修复不在已公开的 v1.5.3 文件中；同名标签和资产保持不可变，1.5.3 不得正式转正。**
