不再维护 `.github/README.md` 和 `.github/README-EN.md` 两份重复页面。GitHub 优先展示 `.github` 中的 README，容易让根目录的更新无法显示在仓库首页；参见 [GitHub README 规则](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)。README 的个人联系方式仅保留邮箱，不再展示 QQ / 飞书联系方式或二维码入口。

安装、Docker 与排错指南已提供中英文；其他详细技术文档按需翻译，各 README 标注链接目标的语言。README 的翻译范围与应用 UI、字幕和模型的语言能力分别维护，不把八语 README 宣称为八语应用支持。

## 更新流程

1. 在同一个 PR 中同步八个 README 的功能、安装条件和配置说明。中文作为内容基准，其他语言允许自然表达，不必逐句直译。
2. 命令、文件名、模型名、参数、下载链接与徽章地址保持一致；不要翻译命令和环境变量。
3. 下载入口使用 `/releases/latest`，平台信息以实际发布资产为准，不在徽章里写死版本号、Stars、Forks 或 Issues 数字。
4. 涉及新平台、功能或导出选项时，先核对实现和发布记录，再同步文案。
5. 在仓库根目录运行 `python3 scripts/check_readmes.py` 和 `git diff --check`。
6. 用 GitHub Markdown 预览核对首屏、语言切换、表格和图片；翻译措辞欢迎母语使用者提交改进。

`I18n Documentation Sync` 工作流检查八语入口、安装与排错文档的本地链接、图片链接、代码块和徽章一致性，不修改文件，也不自动翻译。外部徽章不作为 CI 的网络依赖，避免第三方服务短暂不可用阻断文档更新。检查通过不代表翻译语义已由母语使用者审校。

## 首页维护范围

README 保持简洁，深入说明链接到现有文档。新增文档链接前确认文件存在；增加语言时同步更新八语导航、上表和 `scripts/check_readmes.py` 的文件清单。当前脚本只检查本地链接目标是否存在，不检查外部网站可用性、Markdown 锚点或翻译质量。

界面图片的来源与更新说明见 [素材说明](images/README.md)。个人联系方式仅展示邮箱，维护声明同步八语；无需新增聊天群或即时客服入口。新增中英指南时同步更新检查脚本的 `GUIDES` 清单。
