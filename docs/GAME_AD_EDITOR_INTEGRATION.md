# 游戏创意编辑、语言配置与渲染集成

更新：2026-09-21。状态：产品与接入设计，尚未实现应用内编辑器。依据本地 AutoClip 代码、HyperFrames 0.8.58 文档和三条实际渲染样片。

## 已确认的产品决策

用户在 AutoClip 内完成生成、编辑、预览、变体比较和导出。HyperFrames Studio 不作为必经步骤；默认流程不打开外部网页。Studio 是可选的高级编辑工具。

语言配置独立于 AutoClip 界面语言。至少区分广告文案、对白字幕、配音；纯游戏录屏没有台词时，也能生成广告文案，不制造对白字幕。

三条首轮样片已通过 CLI 输出；Studio 预览单独启动。技术上渲染仍需 Node、Chromium 和 FFmpeg，隐藏交互界面不等于消除这些运行依赖。桌面版由应用管理固定版本的本地工作进程；Web 部署由服务端 worker 执行。首版先接 CLI，不把未经验证的 SDK 或 iframe 双向编辑作为依赖。

## AutoClip 用户流程

1. 在项目页点击「制作广告」，选同游戏素材、渠道、画幅、时长和输出语言。语言支持多选以生成本地化版本。
2. 展示生成的创意卡片，每张提供封面、开头文案、玩法卖点、时长、来源片段和预览。选择一个方向进入编辑。
3. 编辑页面：左侧为素材与候选片段；中间为成片播放器和简化时间轴；右侧为当前片段的文字、字幕、画幅和声音配置。
4. 点击画面文字或右侧字段直接修改；可输入「开头改成英文，保留原声」「去掉底部提示」「把这段缩短两秒」等指令。指令转成可校验的编辑操作，显示更改范围，支持撤销；默认保持未涉及的镜头和声音。
5. 点击「生成变体」，选择开头数量和语言版本；在同一页面比较和勾选。每个语言版本都可单独修改，不覆盖原版本。
6. 导出前显示语言 × 创意 × 画幅的实际组合与数量，确认后后台渲染，页面显示进度、取消、失败重试和下载。

MVP 不复刻完整专业剪辑软件：先支持换片段、调入出点、调整顺序、改文字、改语言、选样式、声音开关与批量导出。复杂自由轨道编辑再迭代。

## 配置项与语义

| 配置 | 首版行为 |
| --- | --- |
| 广告文案语言 | 开头、玩法提示、CTA 按目标地区生成；支持手改和术语锁定。游戏官方名称可独立保留。 |
| 对白字幕 | 关闭 / 原文 / 译文 / 双语；源语言可自动识别或指定。无对白时显示无对白，允许导入 SRT。 |
| 配音 | 默认关闭；未来可选语言、声音和语速，生成后重新检查时长与字幕同步。不得把仅改文字当作完成配音本地化。 |
| 字幕样式 | 字体、字号、颜色、描边、背景、位置、最大行数、关键词强调；可保存项目预设。 |
| 文字图层 | 开头、提示、CTA 分别开关；对白字幕开关不影响这些图层。 |
| 导出 | 烧录字幕 / 单独字幕文件 / 两者；无对白时不输出空字幕文件。 |

优先级：创意版本覆盖 > 项目设置 > 用户默认。项目保存配置快照；用户以后更改默认值，不应改变已经保存的成片。

第一版先完成简中与英文的实际字体和渲染验收，再扩其他语言。语言选项按已验证能力开放，避免只列出语言但出现缺字、错误断行或不支持的配音。

翻译会改变文字长度。每个目标版本重新换行、排版和检查安全区；溢出时优先改写短文案，再在限定字号范围内适配。不能无限缩小文字。底部平台按钮和游戏 HUD 同时参与避让。

## 数据与任务设计

业务真源是 AutoClip 的结构化 `CreativeSpec`，不是生成的 HTML。一个创意包含源片段及时间映射、文字图层、对白字幕、声音、构图、语言版本和模板版本。HyperFrames 工程属于可重新生成的输出。

示意配置（设计契约，非当前已实现 API）：

```json
{
  "schema_version": 1,
  "target_locales": ["zh-CN", "en-US"],
  "copy": {
    "localization": "adapt",
    "enabled_roles": ["hook", "support", "cta"],
    "locked_terms": ["Subway Princess Runner"]
  },
  "captions": {
    "mode": "off",
    "source_locale": "auto",
    "output": "burn_in",
    "style_preset_id": "game-safe-v1",
    "max_lines": 2
  },
  "voiceover": {"enabled": false},
  "audio": {"keep_source": true},
  "canvas": {"width": 1080, "height": 1920, "fps": 30}
}
```

`target_locales` 在批量规划时展开成各自的版本，每个版本持有自己的文案和字幕语言。原文、译文、双语字幕在配置中有明确模式；双语需要保留两种语言的文本及共同时间依据。

修改语言或文案时复用已分析的事件和镜头，不重新跑整段视频理解。仅相关的本地化、排版、配音、检查与渲染任务失效。任务以创意版本、素材散列、配置、字体/模板/模型/渲染器版本构成缓存键，防止修改后下载到旧成片。

后端执行链：保存版本 → 校验编辑方案 → 生成受控模板与本地资产 → HyperFrames check → CLI render → 检查 MP4 → 返回预览和下载地址。任务记录要持久化，支持取消和失败重试；不能直接照搬现有仅内存保存的导出任务表。

不让模型任意 JavaScript 成为默认执行输入：模型优先产出结构化编辑操作，模板由应用控制，渲染进程隔离运行，只访问该任务资产。用户文字作为文本绑定，不能拼成 shell 或脚本执行。

## 预览与 Studio 边界

首版以同一渲染链生成低清 MP4 预览，直接放在 AutoClip 播放器；画幅、时间和文字排版保持与导出一致。编辑未生成新预览时明确标记「预览待更新」，不把草稿截图当作最终成片。

后续可在应用内集成受限 HTML 播放器以加快文字和版式预览，需先验证 seek、媒体加载、字体和与最终渲染的一致性。这与嵌入完整 Studio 是不同工作，不预设现成的双向同步接口。

「高级编辑：在 Studio 打开」可作为可选入口。初版把其产物视为独立分支导出；未经实现并验证的 HTML → CreativeSpec 回写，不承诺可无损返回 AutoClip。普通用户不需要接触工程文件、CLI 或渲染器选择。

## 现有代码接入点与验收

- `frontend/src/pages/ProjectDetailPage.tsx`：现有切片/合集页增加广告创意区和制作入口。
- `frontend/src/components/ClipCard.tsx`：现有发布导出只有画幅、原字幕和标题卡等选项；保留简单导出，广告制作进入独立编辑页面。
- `frontend/src/services/api.ts`：扩展创意版本与渲染任务调用，复用现有进度展示方式。
- `backend/services/publish_export.py`：现有 `subtitles: bool` 不能表达语言、双语和样式；基础导出保持兼容，新的结构化方案通过独立 renderer adapter 执行。
- `backend/api/v1/subtitle_editor.py`：现有字幕驱动删除片段接口不能直接充当广告文字编辑接口。

首版验收：关闭 Studio 后仍可在 AutoClip 完成全流程；中英两版分别保存、编辑与导出；关闭对白字幕不影响 CTA；无对白素材能够成片；长英文不溢出；修改文字不重做素材理解；预览过期可见；任务失败可重试且不覆盖成功版本。现有三条样片只能证明制作链跑通，以上产品交互尚待实现。
