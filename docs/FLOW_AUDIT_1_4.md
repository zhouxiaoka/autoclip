# AutoClip 1.4 分支与端到端流程审计

日期：2026-09-22。被审计代码：`codex/visual-game-ads@96ccfb69`。本报告后的文档提交不改变被测运行代码。

## 结论

游戏录屏 → 视觉候选 → 成片草稿 → 人工编辑 → 包装 → MP4 预览/下载，已有完整代码连接、一次历史真实 Seed 浏览器联调和本次当前代码的 API 串联回归。不能将其表述为“所有路径都验收完”或“已能自动产出起量广告”。

当前实现是视觉辅助选段和开头文案变体，加人工修正及本地渲染。推广模式默认采用首个事件，三种变体主要改变文案；完整多段广告编排、声音设计、收尾设计与买量效果闭环尚未实现。六款文字包装的接受不等于整条创意达到 L2 买量质量。

## 用户全流程与边界

| 环节 | 当前产品行为 | 验证和限制 |
| --- | --- | --- |
| 0. 配置视觉模型 | 设置页保存连接信息，可发测试图片确认理解能力 | 已有接口测试和历史真实联调；“已配置”不等于实时连接成功 |
| 1. 导入录屏 | 首页选择精彩高光/推广成片，上传MP4/MOV/MKV/WebM/AVI或粘贴YouTube/B站链接；设置语言、期望时长、画幅 | 文件路径历史真实联调和本次API串联通过；网络下载、Cookie及平台限制尚未全量验收。首页默认仍是旧内容切片目标 |
| 2. 视觉分析 | FFmpeg抽取最多60张有序静帧，识别最多3个事件；首个事件再以最多25帧复核，保存时间和证据 | 本次真实抽帧11+11张；模型回答使用固定响应。仍是静帧抽样，会漏掉帧间动作；2小时限制不是长录屏效果验收 |
| 3. 生成草稿 | 高光模式按事件生成草稿；推广模式围绕首个事件生成最多3种开头 | 尚非3套不同镜头结构；期望时长约束选段，不保证成片恰好15/30/60秒。分析完成表示草稿就绪，MP4需另行渲染 |
| 4. 人工编辑 | 原片预览、换候选/追加、改起止、重排、撤销、保存；AI修改标题/开头文案 | 已有真实浏览器和媒体回归；AI改文案不会自动重新组织镜头。单稿最多30段、总长30分钟 |
| 5. 成片包装 | 9:16/16:9/原画幅，裁切/完整画面/模糊背景，固定横向取景；六款v6模板及位置/大小/强调色，部分短入场效果 | 12条中英文实际样片、预览/渲染回归。固定取景尚非主角自动跟踪；开头文字仅首镜头最多4秒，不是全片字幕模板 |
| 6. 语言和声音 | 原文/中/英/日，另存独立版本；渲染时翻译开头及已有字幕；保留/关闭原声 | 新视觉导入不自动ASR，也没有SRT上传入口。勾选字幕但无现成字幕时提示并继续无字幕导出。尚无配音/BGM/音效编排 |
| 7. 预览、导出与下载 | 当前文案字层预览；后台FFmpeg裁切拼接、烧录包装，输出H.264/AAC MP4；实际成片播放、下载、历史记录 | 本次API链路输出10秒1080×1920，有声，可下载。源预览不完整模拟剪辑顺序、翻译、字幕或入场动作，最终以实际渲染为准 |
| 8. 版本和恢复 | 草稿修订冲突保护、独立语言版、不可变导出快照、保留历史文件、失败提示和重试 | 部分失败路径有测试；重启后标记失败，尚无断点续跑。连续重试/删除并发/资源与长任务仍需综合回归 |

成片生产路径为AutoClip内的Pillow + FFmpeg，不需要用户打开HyperFrames Studio。仓库中的HyperFrames样片项目属于探索产物，不是正式流水线的必经依赖。

## 证据分层

### A. 历史真实模型 + 浏览器全流程

已有22秒跑酷录屏在实际应用工厂及隔离数据库中，经过真实Seed分析，完成候选编辑、保存/刷新、英文翻译、1080×1920渲染、实际播放和下载事件；详细记录见 `RELEASE_1_4.md` 的“候选镜头与成片链路接通”。当时发生180秒模型超时，设置300秒后成功，整体分析约270秒。该记录早于最终v6模板，不能当作最新整包全量验收。

### B. 本次当前代码的串联回归

被测代码 `96ccfb69`，隔离SQLite与项目目录；真实跑酷素材上传、真实抽帧、真实线程任务、真实FFmpeg及下载接口，仅替换视觉模型和翻译返回。没有付费调用。测试通过，耗时11.55秒；该时间包含固定模型响应，不能代表真实AI分析耗时。

实际顺序：

上传 → 稀疏抽帧11张 → 复核抽帧11张 → 2候选/3推广草稿 → 候选重排16–20秒、8–14秒 → 保存 → 另存英文版 → 标题PNG预览 → 导出 → 状态轮询完成 → MP4下载 → ffprobe。

结果：4份独立草稿，原稿保留；输出10.000秒、1080×1920、H.264/AAC，下载10,405,935字节。这个回归没有操作浏览器，没有测试在线下载或实际模型判断质量。

1. 在最终代码和实际AutoClip页面，用真实模型重新完成一次新录屏导入到下载；保存版本、耗时、画面、音频、字幕有无及实际人工修改记录。不能以独立模板样片审阅页替代产品验收。

3. 明确首发字幕范围为“已有字幕烧录”；新游戏录屏自动语音字幕尚未贯通，若首发要求则另列开发项。卡拉OK继续后置。
4. 补链接下载、模型失败/超时、连续重试、删除与重启、长录屏资源用量回归。
5. 最后整合主线改动、统一1.4版本，验证macOS ARM64/Windows x64安装包和旧项目兼容，再形成RC及发布结论。
